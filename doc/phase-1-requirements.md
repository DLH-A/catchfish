# 第一阶段需求：鱼群游动与炮塔射击

## 目标与范围

实现一个可运行的基础场景：屏幕上持续有鱼游动，底部炮塔跟随鼠标瞄准，点击发射子弹。鱼与子弹各自运动，暂不发生交互。

本阶段不实现碰撞箱、命中检测、伤害、捕鱼、分数、掉落、金币消耗或炮塔升级。

素材使用裴倩蕾上传的.

## 1. 鱼类系统

### 类结构

- `FishBase` 继承 `Component`，实现鱼的公共移动、朝向和基础绘制逻辑。
- 5 种具体鱼继承 `FishBase`，第一版主要通过数值和外观参数区分，不重复实现移动逻辑。
- 基类保存位置、归一化移动方向、速度、大小，以及入场和待移除状态。
- `FishSpawnerComponent` 负责定时生成、持有鱼对象、调用生命周期，以及清理离场的鱼。

### 生成与移动规则

1. 随机选择屏幕左、右、上、下的一条边，在该边外随机生成鱼。
2. 生成位置与屏幕边缘的距离大于鱼的尺寸，保证鱼完整地从屏幕外游入。
3. 随机选择屏幕内的一个目标点，将出生点指向目标点的方向作为移动方向。目标点不是停止点，鱼会继续沿该方向游出屏幕。
4. 鱼保持匀速直线运动，头部朝向移动方向。第一版不做转弯、追踪或群游。
5. 使用 `位置 += 方向 * 速度 * dt` 更新，速度单位为像素/秒。
6. 鱼入场后，等整个身体离开屏幕再移除。不得将刚生成、尚未入场的鱼误判为离场。

### 五种鱼

以下为建议的初始类型，允许调节具体数值：

- `SmallFish`：体型小，速度中等。
- `FastFish`：体型小，速度最快。
- `MediumFish`：体型和速度适中。
- `LargeFish`：体型大，速度慢。
- `RareFish`：体型较大，使用独立颜色，生成概率低于其他鱼。

第一版用不同颜色和大小的简易鱼形代替素材，通过头部标记或尾巴表现朝向。5 种鱼都应有机会生成。

### 生成管理

- 建议初始生成间隔为 1 秒，同时存在的鱼最多 20 条；达到上限时暂停生成，数量下降后恢复。
- 生成间隔、数量上限、各鱼速度、大小和生成权重集中配置，便于调整。
- 使用 `std::unique_ptr<FishBase>` 等明确所有权的方式保存鱼对象。
- 鱼由生成组件管理，不在 `World.update()` 过程中向 `World` 添加鱼。
- 生成组件负责为鱼设置同一个 `Game` 上下文并调用 `Init()`，每帧转发更新和绘制，移除及整体销毁前调用鱼的 `destroy()`。同一条鱼不再重复注册到 `World`。

## 2. 炮塔系统

### 位置与瞄准

- 新增 `TurretComponent`，底座固定在屏幕底部中央，炮管绕底座中心旋转。
- 每帧读取鼠标位置，计算炮塔到鼠标的方向，让炮口朝向鼠标。
- 瞄准范围限制为屏幕上方半圆；鼠标位于下方时，将方向限制到最近的水平边界。
- 鼠标与旋转中心重合时，保留上一次有效方向，避免零向量归一化。
- 第一版使用圆形底座和线段或矩形炮管即可。

### 发射规则

- 鼠标左键每按下一次发射一颗子弹，暂不支持按住连续发射。
- 子弹从炮口生成，沿发射瞬间的炮管方向运动。
- 后续鼠标移动不改变已经射出的子弹方向。
- 点击时使用与该次鼠标位置一致的有效瞄准方向，避免使用上一帧方向发射。
- 不增加金币消耗、炮塔等级、散射或射速升级。

## 3. 子弹系统

- 新增 `BulletComponent`，统一管理子弹的生成、更新、绘制和移除。
- 单颗子弹先作为简单数据对象，保存位置、归一化方向、速度和绘制半径，不要求逐颗注册到 `World`。
- 炮塔通过发射事件通知子弹组件，事件携带炮口位置和发射方向；具体事件类型及事件类需要新增。
- 子弹使用 `位置 += 方向 * 速度 * dt` 匀速直线移动。
- 整颗子弹离开屏幕后移除；移除时不得跳过相邻子弹或破坏遍历。
- 第一版使用圆形绘制，子弹经过鱼时继续飞行，不触发任何交互。

## 4. 开发约定

- **一切玩法皆组件。**`main.cpp` 只负责框架初始化、组件注册、主循环和退出清理，不添加鱼的生成、瞄准、发射等业务逻辑。
- **一个组件负责一类功能。**鱼的公共行为写在基类，各子类配置差异；炮塔负责瞄准和发射通知，子弹组件负责管理子弹。
- **数据由所属组件管理。**不将鱼列表、子弹列表、临时计时器堆进 `Game` 或全局变量。
- **遵守生命周期。**初始化放在 `Init()`，逻辑放在 `update()`，绘制放在 `draw()`，退订和资源释放放在 `destroy()`。
- **使用现有服务。**资源、音频和事件通过 `game` 访问，不重复创建管理器。使用共享资源句柄，不手动卸载管理器返回的纹理或源音效。
- **安全增删对象。**不在 `World` 遍历中增删其组件；组件内部容器采用安全的清理方式。事件同步分发，不保存事件指针，不在回调中修改当前事件的订阅列表。
- **输入只触发一次发射。**若使用内置鼠标事件，注册 `MouseComponent` 并订阅 `EVENT_MOUSE_CLICK`，不要同时在炮塔中重复检测同一次点击。
- 当前 `World` 不自动检查 `isActive`，需要暂停更新或绘制时由组件自行判断。
- 新文件建议放在 `src/gameplay/`，并补齐 VS 文件分组，便于团队成员找到。

## 5. 建议实现顺序

1. 实现 `FishBase` 和一种鱼，验证从屏幕外游入、穿过、离场清理。
2. 实现生成组件和另外四种鱼，加入生成间隔、数量上限和权重配置。
3. 实现炮塔绘制、鼠标瞄准和角度限制。
4. 实现发射事件和子弹管理，接通点击发射。
5. 联调生成、离场、连续点击以及窗口退出时的清理。

## 6. 验收标准

- 能区分 5 种鱼，且都能随机从屏幕外游入，朝向与运动方向一致。
- 鱼入场前不会被误删，离场后能被清理，数量不超过配置上限。
- 炮塔固定在底部中央，跟随鼠标瞄准，方向限制在上方半圆。
- 单次点击只生成一颗子弹，出生位置在炮口，方向与发射时的炮管一致。
- 已发射子弹不随鼠标转向，完全出屏后被移除。
- 鱼与子弹穿过彼此时不发生碰撞或其他交互。
- 改变目标帧率后，鱼和子弹的实际移动速度基本一致。
- 持续运行并多次点击后，离场对象能正常回收，程序无异常退出。
- 玩法逻辑均位于组件中，主循环不增加业务分支；退出时组件和资源得到清理。
